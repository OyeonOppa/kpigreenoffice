# แคมเปญป่า 3R

ทุกคนมีต้นไม้ของตัวเองคนละต้น บันทึกกิจกรรม 3R แล้วได้แต้ม แต้มสะสมทำให้ต้นโตขึ้น
ต้นของคนในสำนักเดียวกันไปยืนรวมเป็นสวน

| หน้า | ใคร | ทำอะไร |
| --- | --- | --- |
| หน้าแรก (hero) | ทุกคน รวมคนนอก | **ป่าของทั้งองค์กร** — ต้นของทุกคนอยู่ในนั้นครบ ล็อกอินแล้วต้นตัวเองมีวงสีทองกำกับ |
| `#/forest` | คนในหน่วยงาน | ปลูกต้นของตัวเอง → บันทึกกิจกรรมรายวัน → ดูต้นตัวเอง/สวนของสำนัก |
| `#/forest/staff` | สตาฟ | ค้นหาคน แล้วกดให้แต้มกิจกรรมพิเศษ (ไม่ได้ลิงก์จากที่ไหน) |
| `#/tree-lab` | คนทำเว็บ | ห้องทดลองปรับหน้าตาต้นไม้ (ไม่ได้ลิงก์จากที่ไหน) |

## หน้าแรกเป็นป่า ไม่ใช่ต้นเดียว

ต้นเดียวบอกได้แค่ "รวมกันแล้วไปถึงไหน" แต่ป่าบอกได้ด้วยว่ามีกี่คนร่วม และแต่ละคนไปถึงระยะไหน
ซึ่งเป็นภาพที่ชวนให้คนอยากมีต้นของตัวเองมากกว่าแถบความคืบหน้าอันเดียว

ข้อมูลมาจาก `subscribeOrg()` ที่ส่ง **ยอดรวม + รายการต้นแบบไม่มีชื่อ** — แต่ละต้นมีแค่
`{ seed, growth }` โดย `seed` เป็นค่าที่ย่อมาจาก uid ไว้สุ่มรูปทรง ไม่ใช่ชื่อและย้อนกลับเป็นคนไม่ได้

ตั้งใจไม่ส่งชื่อมาด้วย เพราะหน้าแรกเปิดให้คนนอกเห็น ถ้าส่งชื่อไปเท่ากับประกาศต่อสาธารณะว่า
ใครในหน่วยงานขยัน/ไม่ขยันเรื่องนี้ เจ้าตัวยังหาต้นตัวเองเจอเพราะคำนวณ `treeSeed(uid)` ของตัวเองได้

## ตัวตน: ชื่อผู้ใช้ + รหัสพนักงาน

บัญชีถูกสร้างไว้ล่วงหน้าจากรายชื่อในองค์กร — ไม่มีการสมัครเอง เข้าเครื่องไหนก็เจอต้นเดิม
เพราะต้นไม้ผูกกับบัญชี ไม่ใช่กับเครื่อง

- **username** = ชื่อภาษาอังกฤษ / ส่วนหน้า @ ของอีเมล (ตั้งตอนสร้างบัญชี)
- **รหัสผ่าน** = รหัสพนักงาน
- **สำนัก** มากับบัญชี ผู้ใช้เปลี่ยนเองไม่ได้ — กำหนดว่าต้นไปยืนในสวนไหน
- ผู้ใช้ตั้งได้แค่ **ตัวละคร** (เลือกตอนเข้าครั้งแรก, เปลี่ยนทีหลังได้จากหน้าต้นของฉัน)

เซิร์ฟเวอร์ตรวจรหัสแล้วคืน **โทเคนที่เซ็นด้วย `SESSION_SECRET`** — หน้าจอเก็บโทเคน ไม่เก็บรหัส
ทุก mutation เซิร์ฟเวอร์อ่าน uid จากโทเคนเอง ค่า uid ที่หน้าจอส่งมาถือเป็นแค่ใบ้

หน้าจอที่เกี่ยวข้องฟังจาก `onAuthChanged` หมดแล้ว (navbar, hero, `#/forest`)

## แต้ม

แต้มมี 2 ทาง — **บันทึกเอง** กับ **สตาฟกดให้**

```
บันทึกเอง   ข้อละ 6–15 แต้ม · ข้อละ 1 ครั้งต่อวัน · รวมไม่เกิน 40 แต้ม/วัน
สตาฟกดให้   1–200 แต้ม · ไม่ติดเพดานรายวัน · ต้องมีเหตุผลกำกับเสมอ
```

### จะรู้ได้ยังไงว่าทำจริง

กิจกรรมแต่ละข้อมี `verify` กำกับใน `content.ts`

```
'qr'    6 ข้อที่ผูกกับจุดจริงในอาคาร — ของจริงต้องสแกน QR ที่ติดตรงจุดนั้นถึงได้แต้ม
'self'  7 ข้อที่ยืนยันไม่ได้ (พกแก้ว ปิดไฟ) — เชื่อคนกด เพราะยังเป็นพฤติกรรมที่อยากส่งเสริม
```

ที่ต้องมี `qr` เพราะถ้าเป็นบันทึกเองล้วน **กด 4 ปุ่มตอนเช้าก็ครบเพดาน 40 แต้มโดยไม่ต้องทำอะไรจริง**
15 วันต้นโตเต็ม แล้วแคมเปญวัดได้แค่ว่าใครขยันกดปุ่ม

QR ยังได้ผลพลอยได้อีกสองอย่าง: บังคับให้เดินไปที่จุดจริง (คือพฤติกรรมที่อยากได้อยู่แล้ว)
และรู้ว่าจุดไหนมีคนใช้จริง เอาไว้ตัดสินใจว่าจะเพิ่ม/ย้ายจุดไหน

ตอนนี้ป้าย "สแกนที่จุด" ขึ้นบนหน้าจอแล้ว แต่ยังกดได้ทุกข้อ — ตัวบังคับอยู่ฝั่งเซิร์ฟเวอร์ที่ยังไม่ได้ทำ

เพดานรายวันมีไว้เพราะถ้าไม่มี คนกดครบทุกข้อในวันเดียวได้ 131 แต้ม = ต้นโตเต็มใน 5 วัน แล้วแคมเปญจบ
เพดาน 40 ทำให้ต้องกลับมาทำต่อเนื่องอย่างน้อย 15 วัน ซึ่งเป็นพฤติกรรมที่แคมเปญต้องการจริงๆ

ชนเพดานกลางคันจะได้แต้มเท่าที่เหลือ ไม่ใช่ถูกปฏิเสธ — คนที่ทำจริงแล้วไม่ควรได้ศูนย์

## การเติบโต

```
growth = แต้มสะสม / 600        (0 = เพิ่งปลูก, 1 = โตเต็มที่)
```

`growth` ส่งตรงเข้า `buildTreeArt()` แล้วออกมาเป็นต้นที่สูงขึ้น แตกกิ่งมากขึ้น ใบเข้มขึ้นอย่างต่อเนื่อง
ระยะทั้ง 10 (`TREE_STAGES`) เป็นป้ายชื่อทับบนค่าต่อเนื่องนี้ ไม่ได้มีโมเดลแยกรายระยะ

```
เมล็ด 0%  หน่ออ่อน 5%  ต้นกล้า 12%  ต้นอ่อน 22%  แตกกิ่ง 34%
ใบแก่เต็มต้น 46%  ทรงพุ่มเต็ม 58%  ออกดอก 70%  ติดผล 84%  ไม้ใหญ่ให้ร่มเงา 100%
```

ช่วงแรกถี่กว่าช่วงหลังโดยตั้งใจ — คนเพิ่งเริ่มต้องเห็นต้นเปลี่ยนระยะภายในไม่กี่วัน
ถ้าระยะแรกยาวเท่าระยะหลัง คนจะกดไปสามวันแล้วรู้สึกว่าไม่มีอะไรเกิดขึ้น

## ต้นไม้เป็น SVG ไม่ใช่ 3D แล้ว

เคยเป็น three.js (`components/forest/`) แล้วรื้อออกทั้งหมด เพราะ:

- ดูไม่สมจริงอยู่ดี — โมเดล low-poly ที่ไล่แสงเองมันอยู่กลางทางระหว่างสมจริงกับการ์ตูน ซึ่งแพ้ทั้งสองทาง
- กินสเปกและโหลดหนัก — ก้อน `Tree3D` อยู่ที่ **889 kB** (236 kB gzip) ใหญ่กว่าโค้ดทั้งเว็บรวมกัน
- ข้อจำกัดของ WebGL บังคับให้ตัดสวนที่ 60 ต้น ทำให้ทำ "ป่าทั้งผืน" ที่หน้าแรกไม่ได้เลย

พอเป็น SVG กฎ 3D ทั้งชุดหายไปพร้อมกัน (Canvas เดียวต่อหน้า, ห้าม unmount Canvas, LOD,
ห้ามไล่ค่า growth ทีละเฟรม, แคชรูปทรงข้ามการวาด) — สลับมุมมองด้วย conditional ธรรมดาได้เลย

เหลือข้อควรระวังข้อเดียว: **จำนวนชิ้นใน DOM ยังโตตามจำนวนต้น**
ป่าจึงใช้ `detail: 'simple'` เสมอ (~32 ชิ้น/ต้น เทียบกับ ~90 ของ `'full'`) และตัดที่ `GARDEN_MAX` 300 ต้น
ที่ระยะป่าต้นสูงราว 40 พิกเซล ความต่างระหว่างกิ่ง 2 ชั้นกับ 4 ชั้นมองไม่เห็นอยู่แล้ว

## โครงไฟล์

```
components/tree/
  stages.ts     TREE_STAGES — ป้ายชื่อ 10 ระยะ + ค่า growth ที่แต่ละระยะเริ่ม
  treeArt.ts    buildTreeArt() สร้างโครงต้นเป็นข้อมูลล้วน (เมล็ด/หน่ออ่อน/ต้นเต็มวัย + ดอก + ผล)
  TreeSvg.tsx   TreeDefs (เกรเดียนต์) · TreeGroup (ต้นเดียว ไม่มี <svg>) · TreeSvg (ต้นเดี่ยวพร้อมกรอบ)
  ForestSvg.tsx ป่าทั้งผืนใน <svg> เดียว + วงสีทองบอกต้นตัวเอง

forest/
  config.ts             FULL_POINTS / DAILY_CAP / GARDEN_MAX / treeSeed  ← ปรับกติกาที่นี่
  types.ts              รูปร่างข้อมูลที่หน้าจอใช้
  backend.ts            interface กลาง — หน้าจอคุยกับหลังบ้านผ่านตัวนี้ตัวเดียว
  mockForestBackend.ts  หลังบ้านจำลอง (localStorage + BroadcastChannel)
  index.ts              จุดสลับ adapter   ← เปลี่ยนไปใช้ของจริงที่บรรทัดเดียวนี้
  hooks.ts              useForestAuth / useForest / useOrgForest

content.ts              FOREST (รายการกิจกรรม + แต้ม + ข้อความ) · ORG_TREE (เป้าของทั้งองค์กร)
pages/                  ForestPage, ForestStaffPage, TreeLabPage
```

**ป้ายชื่อระยะกับรูปที่วาดจริงอยู่ไฟล์เดียวกัน** (`stages.ts`) โดยตั้งใจ —
`treeArt` อ่านค่า growth ของระยะไปใช้เป็นจุดสลับรูปร่าง ถ้าแยกกันคนละไฟล์
วันหนึ่งจะมีป้ายว่า "ออกดอก" ทั้งที่บนจอยังไม่มีดอก

ปรับหน้าตาต้นไม้ที่ `#/tree-lab` — มีทั้งระยะทั้ง 10 เรียงกัน, ต้นเดี่ยวที่เลื่อน growth ได้อิสระ
(ไว้ดูว่ารอยต่อระหว่างระยะต่อเนื่องไหม) และป่าจำลอง 12–250 ต้น

## หลังบ้าน: Cloudflare D1 (มี mock สำรอง)

สลับที่ `index.ts` ด้วย env `VITE_FOREST_API`:

| ตั้ง `VITE_FOREST_API` | ใช้ `cloudflareForestBackend` — Worker + D1 ของจริง (username/รหัสพนักงาน) |
| ไม่ตั้ง | ใช้ `mockForestBackend` — `localStorage` + บัญชีทดสอบ `demo1..demo3` / `staff` |

REST อยู่บน Worker ตัวเดียวกับเกมแยกขยะแข่งสด (`worker/src/forest/`) เส้นทางขึ้นต้น `/api/forest/`
เรียลไทม์ใช้การ **poll ทุก 20 วินาที** (`subscribeForest` / `subscribeOrg`) — จังหวะแคมเปญนี้ไม่ต้องการความสดระดับวินาที

```
worker/src/forest/
  crypto.ts     PBKDF2 แฮชรหัส + โทเคน session (HMAC) — พารามิเตอร์ต้องตรงกับ scripts/gen-users.mjs
  activities.ts แต้มต่อกิจกรรม + DAILY_CAP + GARDEN_MAX (สำเนาจาก src/content.ts / src/forest/config.ts)
  handler.ts    handleForest() — login / session / me / org / profile / activity / award / members
worker/migrations/0001_forest.sql   ตาราง forest_users + forest_points_log
scripts/gen-users.mjs               CSV รายชื่อ → worker/seed/users.sql + credentials.csv
```

### ตั้งครั้งเดียว

```
npx --prefix worker wrangler d1 create kpi-forest
# เอา database_id ใส่ worker/wrangler.jsonc
npx --prefix worker wrangler d1 migrations apply kpi-forest --remote
npx --prefix worker wrangler secret put SESSION_SECRET      # พิมพ์สตริงสุ่มยาวๆ
node scripts/gen-users.mjs รายชื่อ.csv
npx --prefix worker wrangler d1 execute kpi-forest --remote --file=seed/users.sql
npm --prefix worker run deploy
# ตั้ง VITE_FOREST_API ใน Cloudflare Pages = URL ของ Worker แล้ว build ใหม่
```

รันสคริปต์ `gen-users.mjs` ซ้ำได้เพื่อแก้ชื่อ/สำนัก/เพิ่มคน — `ON CONFLICT DO UPDATE` ไม่แตะ `points`/`look_json`

### ยังบังคับที่เซิร์ฟเวอร์แล้ว

ตัวตน (uid จากโทเคน ไม่เชื่อหน้าจอ) · เพดานรายวัน · กันบันทึกกิจกรรมซ้ำต่อวัน (unique index)
· ขอบเขตของวันตรึงเป็นเขตเวลาไทย · สิทธิ์สตาฟ (`role='staff'`) · สวนส่งเฉพาะ `GARDEN_MAX` ต้น + ตัวเลขสรุป

## สิ่งที่ยังไม่ได้ทำ

- **QR ประจำจุด** — ยังไม่มี endpoint ตรวจ token ประจำจุด กิจกรรม `verify:'qr'` ตอนนี้กดได้เลย
- **กระดานระดับสำนัก** — ควรวัดด้วย **แต้มเฉลี่ยต่อหัว ไม่ใช่แต้มรวม** ไม่งั้นสำนักใหญ่ชนะทุกเดือน
- **รายการกิจกรรมจริง** — 13 ข้อใน `FOREST.activities` เป็นตัวตั้งต้น ต้องให้คณะทำงานเคาะ
  แก้แต้ม/เพิ่ม/ลบ ต้องแก้ `worker/src/forest/activities.ts` ให้ตรงด้วย แล้ว deploy worker ใหม่
- **ดอกกับผลยังเป็นวงกลม** — อ่านออกจากสีและตำแหน่ง แต่ยังไม่มีกลีบหรือก้าน
- **แต้มจากเกมแยกขยะแข่งสด** — ยังไม่ได้ต่อเข้าด้วยกัน
- **บังคับเปลี่ยนรหัสครั้งแรก** — ไม่ได้ทำ (รหัส = รหัสพนักงาน คนอื่นเดายาก ยอมรับความเสี่ยงระดับนี้)
