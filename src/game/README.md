# เกมแยกขยะแข่งสด (Live Quiz)

เกมแข่งพร้อมกันทั้งหน่วยงานแบบ Kahoot — ลากขยะลงถังให้ถูกและให้ไว

| หน้า | ใคร | ทำอะไร |
| --- | --- | --- |
| `#/live` | ผู้เล่น (มือถือ) | สแกน QR / ใส่ PIN → ตั้งชื่อ + แต่งตัวละคร → ลาก/แตะถัง → ดูเฉลย → ดูอันดับ |
| `#/live/host` | สตาฟ (จอโปรเจกเตอร์) | สร้างห้อง → โชว์ PIN → กดเริ่ม → คุมจังหวะ → ประกาศผล → โหลด CSV |
| `#waste-game` | ทุกคน | เกมเดิมเล่นคนเดียวในหน้าแรก (ไม่เกี่ยวกับโมดูลนี้) |

**ไม่มีล็อกอิน** — ใครสแกน QR หรือกรอก PIN ก็เข้าเล่นได้เลย เบราว์เซอร์สร้าง `uid` สุ่มเก็บไว้ในเครื่อง
ใช้แค่ผูก "คนเดิม" ตอน reconnect กับตัดสินว่าใครเป็นสตาฟ (คนแรกที่เปิดห้อง) ด่านเดียวที่กันคนนอกคือ
`ALLOWED_ORIGINS` ใน `wrangler.jsonc` ต้องมีโดเมนเว็บจริงของหน่วยงาน

## จังหวะเกม

```
lobby → countdown(3s) → answering(10s) → reveal(4s) → explain(6s) → board(5s)
                            ↑                                          │
                            └──────────── ข้อถัดไป ────────────────────┘
                                                                       ↓
                                             finale (เฉลยอันดับ 10 → 1 ทีละ 2.5s) → ended
```

15 ข้อ ≈ 7 นาที รวมเปิด-ปิด ≈ 10 นาที ปรับเวลาทุกค่าได้ที่ [`config.ts`](./config.ts)

## คะแนน

```
ตอบถูก  = 500 + 500 × (เวลาที่เหลือ / 10 วิ)      →  500–1000
โบนัสถูกติดกันตั้งแต่ข้อที่ 3 = +100/ข้อ (เพดาน +300)
ตอบผิด / ไม่ตอบ = 0
```

เวลาที่ใช้ตอบคำนวณจาก **เวลาฝั่งเซิร์ฟเวอร์** เสมอ (เวลาที่บันทึกคำตอบ ลบ เวลาที่ข้อเริ่ม)
ตัวนับถอยหลังบนมือถือเป็นแค่ภาพ แก้โค้ดฝั่งผู้เล่นก็โกงเวลาไม่ได้
ตัดสินกรณีคะแนนเท่ากันด้วยเวลารวมที่ใช้ตอบ

## โครงไฟล์

```
game/
  config.ts       เวลาแต่ละเฟส + สูตรคะแนน  ← ปรับจังหวะเกมที่นี่
  types.ts        รูปร่างข้อมูลที่หน้าจอใช้
  questions.ts    แปลงคลังคำถามจาก content.ts + สุ่มข้อแบบคละถัง
  backend.ts      interface กลาง — หน้าจอคุยกับหลังบ้านผ่านตัวนี้ตัวเดียว
  mockBackend.ts  หลังบ้านจำลอง (localStorage + BroadcastChannel)
  index.ts        จุดสลับ adapter   ← เปลี่ยนไปใช้ของจริงที่บรรทัดเดียวนี้
  hooks.ts        useAuth / useRoom / useNow / useHashRoute
  sfx.ts          เสียงประกอบ สังเคราะห์ด้วย Web Audio ไม่ต้องมีไฟล์เสียง
  avatar.ts       สุ่ม/ประกอบตัวละครประจำตัวผู้เล่น

game/hooks.ts     useHashQueryParam อ่าน ?pin=... ที่ต่อท้าย hash (มาจาก QR)

components/live/  MascotBin, DragArena, CountdownRing, AnswerBars, Leaderboard,
                  Confetti, PlayerAvatar, JoinQr, LiveShell
pages/            LivePlayerPage, LiveHostPage
content.ts        LIVE_GAME (ตั้งค่า/ทีม) + AVATAR_PARTS (ชิ้นส่วนตัวละคร) + LIVE_QUESTIONS (คำถาม + คำอธิบาย)
```

## หลังบ้าน: Cloudflare Worker + Durable Object

หนึ่งห้อง = Durable Object หนึ่งตัว ตั้งชื่อด้วย PIN ผู้เล่นทุกคนต่อ WebSocket เข้ามาที่ object เดียวกัน

**เซิร์ฟเวอร์เป็นเจ้าของทุกอย่าง** — นาฬิกา (ผ่าน alarm), คะแนน และคำเฉลย
เครื่องสตาฟเหลือหน้าที่แค่กดปุ่มกับแสดงผล ถ้าเน็ตเครื่องสตาฟสะดุด เกมยังเดินต่อให้ผู้เล่นทุกคน

```
worker/
  wrangler.jsonc   ตั้งค่า binding + migration (ต้องเป็น new_sqlite_classes)
  src/index.ts     เราเตอร์: POST /api/room สร้างห้อง, /api/ws ต่อ WebSocket
  src/room.ts      GameRoom — ตัวเกมทั้งหมด
  src/config.ts    เวลาและสูตรคะแนน (ของจริง ฝั่งเว็บมีสำเนาไว้วาดวงแหวนเฉยๆ)
  src/questions.ts คลังคำถาม + คำเฉลย  ← ไม่เคยออกจากเซิร์ฟเวอร์
  src/protocol.ts  รูปแบบข้อความ (ต้องตรงกับ src/game/protocol.ts)
```

### คำเฉลยไม่อยู่บนเครื่องผู้เล่น

นี่คือเหตุผลหลักที่ย้ายมาใช้ DO และมีตัวตรวจอัตโนมัติกันหลุด:

```bash
npm run check:answers
```

รันหลัง `npm run build` — ถ้าคำเฉลยหลุดเข้า bundle จะ fail ทันที
(ตัวเลือกหลังบ้านทำเป็น alias ที่ `vite.config.ts` โมดูลจำลองจึงไม่เข้ากราฟตั้งแต่แรก
ไม่ได้พึ่ง tree-shaking ซึ่งลองแล้วตัดไม่ขาด)

เช็คแล้วได้ผลตามนี้: build โหมดจริง 458.91 kB ไม่มีคำเฉลย · build โหมดจำลอง 483.40 kB มีคำเฉลย

### ยังมีโหมดจำลองอยู่

ไม่ตั้ง `VITE_LIVE_API` = ใช้ `mockBackend` เก็บสถานะใน localStorage ซิงก์ข้ามแท็บด้วย BroadcastChannel
เปิดหลายแท็บในเครื่องเดียวกัน = ซ้อมได้ครบทุกขั้นโดยไม่ต้องรันเซิร์ฟเวอร์
ใช้ได้เฉพาะในเครื่องเดียวกัน ใช้จริงในงานไม่ได้

## รันในเครื่อง

เปิดสองหน้าต่าง:

```bash
npm run worker:dev    # Worker ที่ http://127.0.0.1:8787
npm run dev           # เว็บที่ http://localhost:5173
```

`.env.local` ต้องมี `VITE_LIVE_API=http://127.0.0.1:8787`
ยังไม่ต้องมีบัญชี Cloudflare — wrangler รัน Durable Object ในเครื่องได้เลย

## ขึ้นใช้งานจริง — ทำ 2 อย่าง

**1. deploy Worker**

```bash
npm --prefix worker run deploy      # = wrangler deploy (ครั้งแรก wrangler จะให้ล็อกอิน Cloudflare)
```

ก่อน deploy แก้ `worker/wrangler.jsonc` → `ALLOWED_ORIGINS` ให้มีโดเมนเว็บจริงของหน่วยงานเป็นตัวแรก
(เกมไม่มีล็อกอิน ด่านนี้เป็นด่านเดียวที่กันคนนอก — อย่าใส่ `*` หรือปล่อยว่าง)

**2. ตั้ง `VITE_LIVE_API`** เป็น URL ของ Worker ที่ deploy แล้ว (`https://kpigreenoffice-live.<subdomain>.workers.dev`)
ใส่ในตัวแปร build ของ Cloudflare Pages แล้ว build เว็บใหม่

### ทดสอบโหลดก่อนงานจริง

```bash
# 1) เปิดจอ Host เอา PIN มาก่อน (อย่าเพิ่งกดเริ่ม)
# 2) ยิงผู้เล่นปลอม 250 คนเข้าห้อง
node scripts/loadtest.mjs https://kpigreenoffice-live.<subdomain>.workers.dev <PIN> 250
# 3) กดเริ่มเกมที่จอ Host แล้วดูว่าจอเดินลื่น ตัวเลขคนตอบขึ้นครบ  · Ctrl+C เพื่อปิด
```

## รองรับ 250 คนพร้อมกันไหม

**รองรับ** และแผนฟรีของ Cloudflare ครอบคลุมงานขนาดนี้

Durable Objects ใช้ได้บนแผนฟรี (เฉพาะแบบ SQLite backend ซึ่งเราตั้งไว้แล้ว)
โควตาฟรี: 100,000 requests/วัน และ 13,000 GB-s/วัน

ประมาณการต่อ 1 เกม (250 คน × 15 ข้อ):
- requests ~4,000 (ต่อ WebSocket 250 + ข้อความคำตอบ 3,750) จากโควตา 100,000/วัน
- duration ~75 GB-s (DO ตื่นอยู่ราว 10 นาที × 128 MB) จากโควตา 13,000/วัน
- **ซ้อมแล้วเล่นจริงวันเดียวกันได้สบาย** ต่างจาก Firestore ที่โควตาฟรีพอแค่วันละรอบ

**ยิงโหลดจริง 250 การเชื่อมต่อแล้ว** (local wrangler + `scripts/loadtest.mjs`)
250/250 ต่อติด เข้าห้องครบ 0 error · ตอนสตอร์ม join ไต่ 9→103→199→250 ไม่มีสะดุด ·
แต่ละข้อ `answered` ไต่ถึง ~220/250 ในช่วงตอบ · ทุกเฟสเปลี่ยนตรงเวลาเป๊ะ ไม่มี backlog

**สิ่งที่ออกแบบเผื่อ 250 คนไว้แล้ว**

| ปัญหา | ที่ทำไว้ |
| --- | --- |
| ส่งรายชื่อทั้งห้องให้ทุกเครื่อง (~50 KB × 250) | เครื่องผู้เล่นได้แค่ `me` + `playerCount` + กระดาน 10 อันดับ ส่วน `roster` ส่งให้เครื่องสตาฟเท่านั้น |
| สตอร์ม join ตอนคนสแกน QR พร้อมกัน (broadcast เต็มห้องต่อ 1 คนที่เข้า = O(N²)) | `queueRoomBroadcast()` รวบให้ถี่สุด ~2.5 ครั้ง/วินาที (ตัวเลขในล็อบบี้ไม่ต้องเป๊ะวินาที) |
| ตัวนับ "ตอบแล้ว X คน" ยิงทุกคำตอบ | หน่วงเป็นวินาทีละครั้ง |
| ตอนเปลี่ยนเฟส query อันดับทีละคน 250 รอบ | จัดอันดับ + ดึงผลรายข้อครั้งเดียว แล้วแจกเข้า socket แต่ละเส้น |
| serialize ข้อความซ้ำ 250 รอบ | สร้าง JSON ก้อนเดียวแล้ว loop ส่ง |
| ห้องรอกินซีพียูตอนไม่มีอะไรเกิดขึ้น | ใช้ `acceptWebSocket` (Hibernation API) DO หลับได้ระหว่างรอ |
| กำแพงอวตารในห้องรอ 250 ตัว | โชว์ 60 คนล่าสุด + "และอีก N คน" |
| DO ถูกอีวิคกลางเกมแล้วสถานะหาย | สถานะทั้งหมดอยู่ใน SQLite ของ DO ไม่ได้อยู่แต่ในหน่วยความจำ |

**ข้อกังวลที่เหลือ**

1. **เน็ตของผู้เล่น** — ไม่ต้องต่อไวไฟเดียวกัน ใครใช้เน็ตอะไรก็ได้ แนะนำให้ใช้เน็ตมือถือด้วยซ้ำ
   ไวไฟตัวเดียวรับ 250 เครื่องคือจุดที่เปราะที่สุด ข้อมูลต่อคนต่อข้อมีแค่ไม่กี่ KB
2. **เวลาที่โจทย์ไปถึงแต่ละเครื่องไม่เท่ากัน** — ต่างกันราว 100–400 ms คิดเป็นคะแนน 5–20
   จากโบนัสความไวเต็ม 500 เทียบกับคะแนนพื้นฐาน 500 ถือว่ารับได้

## สิ่งที่ยังไม่ได้ทำ

- **deploy Worker ขึ้น Cloudflare จริง + ตั้ง `VITE_LIVE_API` ที่ Pages** — โค้ดพร้อมแล้ว รันได้ครบใน local
- **ทดสอบโหลดบน Worker ตัวจริง** — ที่ยิงแล้ว 250 คนคือบน wrangler ในเครื่อง
- **รูปไอเท็มใหม่ 16 ชิ้น** — ข้อที่ยังไม่มีไฟล์ `.webp` จะ fallback ไปแสดง emoji อัตโนมัติ
  รายชื่อไฟล์ที่ต้องเพิ่มดูได้จาก field `image` ใน `LIVE_QUESTIONS`
- **ตรวจทานคำเฉลย** — ข้อที่ทำเครื่องหมาย `checkLocal` ขึ้นกับว่าหน่วยงานมีจุดรับเฉพาะหรือไม่

## หมายเหตุตอนใช้งานจริง

- เครื่องสตาฟเปิดหน้า `#/live/host` ค้างไว้เพื่อแสดงผล แต่ **ไม่ได้เป็นตัวจับเวลาแล้ว**
  ตัวจับเวลาอยู่ที่ Durable Object เน็ตเครื่องสตาฟสะดุดหรือสลับแท็บ เกมก็ยังเดินต่อให้ทุกคน
- ผู้เล่นรีเฟรช เน็ตหลุด ล็อกจอ **หรือปิดแท็บ/เบราว์เซอร์ crash** แล้วเปิดกลับมาได้ เป็นคนเดิม
  เพราะ `uid` เก็บใน `localStorage` (ไม่ใช่ `sessionStorage` ที่รอดแค่ตอนรีเฟรช) คะแนน/คำตอบเดิม
  อยู่ที่ Durable Object ไม่หาย · WebSocket ต่อกลับเองแบบถอยเวลารอเพิ่มขึ้น (0.5→10 วิ)
  ถ้าหลุดพอดีช่วง 10 วิที่ตอบ ข้อนั้นได้ 0 ตามปกติ แต่ข้อถัดไปเล่นต่อได้
- คนมาสายเข้าไม่ได้หลังกดเริ่มเกม (กันปัญหาความยุติธรรม) รอรอบถัดไป
